# Free-tier infrastructure proposal

`main.tf` pins the Cloudflare provider. It describes one D1 database per **two consecutive corpus years** (seven for 2014–2026). The 2022–2023 pilot already exists and is referenced by its ID; Terraform does not manage it. The six proposed databases have `prevent_destroy`. This configuration does not manage the Vercel site. No `terraform apply` has run.

The final shard is named `dail-debates-2026-2027` even though the current output maps only 2026. This keeps the database identity stable when 2027 debates become available.

For the existing pilot, set `TF_VAR_pilot_start_year=2022` before `terraform plan`. A 5 October 2026 offline plan with placeholder account ID and no Cloudflare credential showed **zero resource changes** and mapped 2022 and 2023 to the existing database `ec1bb53b-f607-4c81-8294-9683f4d8800d`. The wider offline plan proposed **six additions, zero changes, zero destroys**, excluding that pilot. These plans do not verify provider access or authorize an apply. The earlier one-addition pilot plan is obsolete.

## Live D1 pilot, 5 October 2026

The single free-plan database `dail-debates-2022-2023` was created with EU jurisdiction; Cloudflare reports region `EEUR`. It has the same `passages` table, date index, and FTS5 schema used by `scripts/publish_d1.py`. The first ten passages were short examples from 19 January 2022 and 18 January 2023. A second, deterministic random sample added ten passages per year with 300–4,000 characters of text. The query API verified **30 passage rows**. This is deliberately not full-year coverage.

Cloudflare reported **188,416 bytes** and 30 passages after the second sample. Exact-match FTS searches for `Stáit` and `teachers` each returned the expected passage and Official Report URL. A direct read preserved `Tá`, `Stáit`, `Teachtaí`, `Ó`, and `Cuív`. The application's ranked FTS query with a 2023 date filter also returned three linked `climate` passages; D1 reported 1.1254 ms SQL duration, 9 rows read, and zero rows written. That duration excludes network, application processing, and generation. It does not establish public query latency. The initial Windows console export replaced some fadas, so the first ten pilot rows were reloaded from the original SQLite with ASCII-escaped JSON and verified. The schema, first import, correction, and second sample reported approximately 176 D1 rows written in total.

The local 2022–2023 shard contains **76,815 passages** with 97,609,495 characters of text. D1 reported 80 rows written for the 20 new passages, or four counted writes per passage with this schema. A full import would therefore take at least four UTC days under the account's 100,000-row daily free write limit, even with no other account writes. The sample's storage growth gives a rough 393 MB extrapolation, but 20 passages selected from a restricted length range cannot establish that the entire shard fits D1's 500 MB database limit. Do not run an unattended full import or launch public Q&A on this sample.

The machine-readable pilot result is in [`docs/results/d1-pilot-2026-10-05.json`](../docs/results/d1-pilot-2026-10-05.json).

The original 3 October 2026 offline plan proposed 13 databases, which exceeds Cloudflare's current **10 D1 databases per Workers Free account** limit. The revised two-year layout needs seven in total, counting the existing pilot. The 2022–2023 local SQLite FTS shard measured **326,537,216 bytes** on 5 October 2026, below the **500 MB per-database** free cap. This is local SQLite sizing, not a measured D1 import. Terraform 1.13.5 `fmt -check` and `validate` passed for this revision. A full offline plan with a placeholder account ID proposed **six additions, zero changes, zero destroys**. Run an authenticated plan and check actual D1 storage and account usage before considering any apply. The user has reserved `terraform apply` for explicit approval.

Two-year shards are still a candidate: the downloaded XML measures 787.7 MB and the complete local FTS index 1.86 GB. Separate 2014 and 2026 SQLite shards measured 147.2 MB and 126.0 MB. Cloudflare's free plan caps a single D1 database at 500 MB and total account D1 storage at 5 GB, with 100,000 rows written and five million rows read per day. The importer in `scripts/publish_d1.py` now defaults to 5,000 passages and reports D1's `rows_written` metadata, but that script has not been exercised against the account because the scoped OAuth grant is not exposed as a shell token. Its per-run count is not an account-wide daily quota. Measure a representative larger batch, inspect actual usage and storage, and adjust future batches accordingly. Provisioning a database alone does not make public Q&A available. API credentials, production storage and latency measurements, a reviewed evaluation set, citation checks, and a deployed end-to-end smoke test remain release gates.

The FastAPI rate and daily request limiters are process-local. A public multi-instance deployment needs a shared quota counter or an edge rule that enforces the same limit across instances. Workers AI's provider quota is a final free-tier stop, not a substitute for public abuse control.
